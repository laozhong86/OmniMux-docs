OmniMux 对外集成有 **两条主入口**：

| 入口 | Base URL | 凭证 | 典型用途 |
| --- | --- | --- | --- |
| **AI 网关** | `https://api.omnimux.ai` | `sk-` Bearer | Chat、图像、视频、音频、嵌入… |
| **用户 API** | `https://omnimux.ai` | access token + `New-Api-User` | Social Ops、设备码登录等 |

控制台：[omnimux.ai/dashboard](https://omnimux.ai/dashboard) · 文档：[docs.omnimux.ai](https://docs.omnimux.ai)

## 怎么读本手册

本站 **API 手册** 采用混合信息架构（系列发现 + 协议对接）：

1. **系列导读** — 按「我要出图 / 出视频 / 出音频 / 发社媒」进入  
2. **通用约定** — 设备码登录、异步 `task_id` 轮询  
3. **协议集成** — 已有 OpenAI / Claude / Gemini SDK 时按路径对照  
4. **附录 OpenAPI** — AI 网关 schema 与 try-it（不含 Social Ops）

收录边界见 [文档覆盖说明](/cn/api-reference/coverage)。

## AI 网关快速鉴权

```http
Authorization: Bearer sk-xxxxxxxx
Content-Type: application/json
```

令牌在控制台 **令牌 / API Keys** 创建。OpenAI 兼容 SDK 的 Base URL 通常为：

```text
https://api.omnimux.ai/v1
```

## 模型 ID

请求中的 `model` 必须是你账户当前可用的标识：

```bash
curl https://api.omnimux.ai/v1/models \
  -H "Authorization: Bearer $OMNIMUX_API_KEY"
```

不要把文档示例名当成可用性证明。详见 [模型列表](/cn/guides/models)。

## 错误速查

| HTTP | 常见原因 |
| --- | --- |
| `401` | 缺少 / 错误的 Bearer Token，或混用了 access token 与 `sk-` |
| `403` | 令牌未授权该模型或 IP 受限 |
| `404` | 路径错误，或 Base URL 多写/少写 `/v1` |
| `429` | 限流 |
| 额度类错误 | 账户或令牌配额不足 |
