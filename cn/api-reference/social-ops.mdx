title: "Social Ops（社媒运营）"
description: "绑号、媒体上传与发帖 API。不经模型广场；使用用户 access token，不是 sk- 中继密钥。"
---

Social Ops 把多平台社媒能力（上游 Zernio）以 **用户 API** 形式开放。当前控制台尚无完整「绑号」UI，但 **HTTP 接口已对登录用户开放**；[OmniMux CLI](https://github.com/laozhong86/omnimux-cli) 的 `omnimux social *` 即调用本接口。

**不需要**在模型广场配置模型，也 **不要**用 `sk-` 网关令牌调这些路径。

## Base URL

```text
https://omnimux.ai
```

完整路径前缀：`/api/social/v1`。  
注意：与 AI 网关 `https://api.omnimux.ai/v1` **不是同一套入口**。

实例需开启 Social Ops（生产已开）。先探测：

```bash
curl -sS https://omnimux.ai/api/social/v1/status
```

## 鉴权

需要 **用户 access token**（与 `omnimux login` / 控制台系统访问令牌同类），并带上用户 ID：

```http
Authorization: Bearer <access_token>
New-Api-User: <user_id>
Content-Type: application/json
```

| 凭证 | 用途 |
| --- | --- |
| access token + `New-Api-User` | Social Ops、控制台用户 API |
| `sk-...` | 仅 AI 网关 `/v1/...`（Chat、图像、视频等） |

获取 access token 的常见方式：

1. CLI：`omnimux login`（写入本机 Keychain / secrets）
2. 控制台登录后生成的系统访问令牌（以控制台实际能力为准）

## 接口一览

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| `GET` | `/api/social/v1/status` | 否 | 是否启用、平台白名单 |
| `GET` | `/api/social/v1/accounts` | 是 | 当前用户已连接账号 |
| `POST` | `/api/social/v1/connect` | 是 | 获取 OAuth 授权 URL |
| `DELETE` | `/api/social/v1/accounts/{id}` | 是 | 断开账号 |
| `POST` | `/api/social/v1/media/presign` | 是 | 媒体预签名上传 |
| `POST` | `/api/social/v1/posts` | 是 | 发帖 / 排期 |
| `GET` | `/api/social/v1/posts/{id}` | 是 | 查询发帖状态 |

响应统一 envelope：

```json
{ "success": true, "message": "", "data": { } }
```

失败时 `success: false`，并可能带 `code`（如 `SOCIAL_OPS_DISABLED`、`SOCIAL_ACCOUNT_DENIED`、`SOCIAL_MEDIA_INVALID`）。

## GET /api/social/v1/status

探测功能是否可用。

```bash
curl -sS https://omnimux.ai/api/social/v1/status
```

`data` 字段示例：

| 字段 | 说明 |
| --- | --- |
| `enabled` | 是否开启 |
| `upstream_ready` | 上游密钥是否已配置 |
| `platforms` | 允许连接的平台列表（如 `tiktok`） |
| `provider` | 上游标识（`zernio`） |
| `billing_mode` | 当前多为 `off`（只审计） |

## GET /api/social/v1/accounts

列出 **当前用户** 已绑定且 active 的账号（自动与上游同步）。

```bash
curl -sS https://omnimux.ai/api/social/v1/accounts \
  -H "Authorization: Bearer $OMNIMUX_ACCESS_TOKEN" \
  -H "New-Api-User: $OMNIMUX_USER_ID"
```

`data.accounts[]`：

| 字段 | 说明 |
| --- | --- |
| `id` | OmniMux 侧账号 ID（发帖时用） |
| `platform` | 如 `tiktok`、`twitter` |
| `username` / `display_name` | 展示信息 |
| `status` | 如 `active` |

## POST /api/social/v1/connect

发起平台 OAuth，返回浏览器授权 URL。

```bash
curl -sS -X POST https://omnimux.ai/api/social/v1/connect \
  -H "Authorization: Bearer $OMNIMUX_ACCESS_TOKEN" \
  -H "New-Api-User: $OMNIMUX_USER_ID" \
  -H "Content-Type: application/json" \
  -d '{"platform":"tiktok","redirect_url":"https://omnimux.ai/"}'
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `platform` | 是 | 见 status 的 `platforms`；`x` 会规范为 `twitter` |
| `redirect_url` | 否 | 授权完成后的落地页；须为 https，或与实例默认回调同 host |

成功 `data`：

| 字段 | 说明 |
| --- | --- |
| `auth_url` | 打开此 URL 完成授权 |
| `platform` | 规范化后的平台名 |

用户在浏览器完成授权后，再调 `GET /accounts` 应能看到新账号。

## DELETE /api/social/v1/accounts/\{id\}

断开本用户名下账号（`id` 为 OmniMux 侧 id）。

```bash
curl -sS -X DELETE "https://omnimux.ai/api/social/v1/accounts/1" \
  -H "Authorization: Bearer $OMNIMUX_ACCESS_TOKEN" \
  -H "New-Api-User: $OMNIMUX_USER_ID"
```

## POST /api/social/v1/media/presign

申请上传地址。客户端把文件 **PUT 到 `upload_url`**（不经 OmniMux 中转），再把 `public_url` 用于发帖。

```bash
curl -sS -X POST https://omnimux.ai/api/social/v1/media/presign \
  -H "Authorization: Bearer $OMNIMUX_ACCESS_TOKEN" \
  -H "New-Api-User: $OMNIMUX_USER_ID" \
  -H "Content-Type: application/json" \
  -d '{"filename":"clip.mp4","content_type":"video/mp4","size_bytes":1234567}'
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `filename` | 是 | 文件名 |
| `content_type` | 是 | 如 `image/png`、`video/mp4`（白名单 MIME） |
| `size_bytes` | 否 | 字节数（客户端可先校验） |

`data`：

| 字段 | 说明 |
| --- | --- |
| `upload_url` | 直传 PUT 地址 |
| `public_url` | 发帖时写入 `media_items` |
| `headers` | 建议 PUT 时使用的头（如 `Content-Type`） |

```bash
curl -sS -X PUT "$UPLOAD_URL" \
  -H "Content-Type: video/mp4" \
  --data-binary @./clip.mp4
```

## POST /api/social/v1/posts

创建发帖或排期。只能使用 **自己** 的 `account_ids`。

```bash
curl -sS -X POST https://omnimux.ai/api/social/v1/posts \
  -H "Authorization: Bearer $OMNIMUX_ACCESS_TOKEN" \
  -H "New-Api-User: $OMNIMUX_USER_ID" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $(uuidgen)" \
  -d '{
    "content": "Hello from OmniMux",
    "account_ids": [1],
    "publish_now": true,
    "media_items": [{ "url": "https://media.example.com/a.png" }]
  }'
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `account_ids` | 是 | OmniMux 账号 id 列表 |
| `content` | 与媒体二选一 | 文案 |
| `media_items` | 与文案二选一 | `[{ "url": "…", "type": "image\|video" }]`，`type` 可省略 |
| `publish_now` | 否 | 默认立即发；有 `scheduled_for` 时为排期 |
| `scheduled_for` | 否 | ISO8601 时间 |
| `timezone` | 否 | 时区 |
| `queued` | 否 | 走上游队列（若启用） |

幂等：请求头 `Idempotency-Key` 或 `X-Idempotency-Key`。

`data` 含 `id`（OmniMux 帖子 id）、`status`、`provider_post_id` 等。

---

## GET /api/social/v1/posts/\{id\}

查询本用户发帖状态。默认 `refresh=1` 会尽量向上游刷新。

```bash
curl -sS "https://omnimux.ai/api/social/v1/posts/1" \
  -H "Authorization: Bearer $OMNIMUX_ACCESS_TOKEN" \
  -H "New-Api-User: $OMNIMUX_USER_ID"
```

## CLI 对照

| CLI | API |
| --- | --- |
| `omnimux social status` | `GET …/status` |
| `omnimux social accounts` | `GET …/accounts` |
| `omnimux social connect --platform tiktok` | `POST …/connect` |
| `omnimux social disconnect <id>` | `DELETE …/accounts/{id}` |
| `omnimux social media upload <path>` | presign + 本地 PUT |
| `omnimux social post --accounts …` | `POST …/posts` |
| `omnimux social post-status <id>` | `GET …/posts/{id}` |

CLI 安装与版本见 [omnimux-cli Releases](https://github.com/laozhong86/omnimux-cli/releases)。

## 与 AI 网关的关系

| | Social Ops | AI 网关 |
| --- | --- | --- |
| Base | `https://omnimux.ai` | `https://api.omnimux.ai` |
| 路径 | `/api/social/v1/...` | `/v1/...` |
| 凭证 | access token + `New-Api-User` | `sk-` |
| 模型名 | 不需要 | 需要 |
