# i18n (docs site)

## Model

Mintlify **dual tree** — not string-key i18n:

```text
docs.json → navigation.languages[]
  language: cn (default: true) | en
  tabs → groups → pages: "cn/…" | "en/…"
cn/**  ↔  en/**   same relative paths
```

- Default locale: **cn** (root redirects into CN content).  
- Language code **`cn`** is project-local (Mintlify docs list `zh` / `zh-Hans` / `zh-CN`). Live switcher shows 简体中文; migrating to `zh` is a **high-risk path change** (redirects + product links) — not default work.  
- Product terms in EN may keep Chinese tokens when they are product UI language (e.g. **积分**).  
- Brand / model ids / platform names stay untranslated.

## Hard rules

1. Same relative path under `cn/` and `en/`.  
2. `docs.json` nav sets equal after stripping `cn/` / `en/`.  
3. No cross-locale internal links.  
4. Social-data EN Response examples must include the same status set as CN (**200 + 400/401/402/403/429/500/502**).  
5. Lint: `python3 scripts/check-i18n.py`.

## Out of scope

- Product app `web/src/i18n`.  
- Third locales (ja, zh-TW, …) without product decision.  
- Changing default language to `en` without product decision.
