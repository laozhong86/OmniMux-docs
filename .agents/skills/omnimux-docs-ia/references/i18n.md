# i18n (docs site)

## Model

Mintlify **dual tree** — not string-key i18n:

```text
docs.json → navigation.languages[]
  language: en (default: true) | zh
  tabs → groups → pages: "en/…" | "zh/…"
en/**  ↔  zh/**   same relative paths
```

- **Default locale: `en`** (root → `/en/quickstart` via `default` + soft redirect).  
- **Chinese locale code: `zh`** (directory `zh/`). Official Mintlify codes include `zh` / `zh-Hans` / `zh-CN`.  
- **Legacy `/cn/*`**: permanent redirects to `/zh/*` in `docs.json` `redirects` (keep ≥ 6–12 months).  
- Product terms in EN may keep Chinese tokens when they are product UI language (e.g. **积分**).  
- Brand / model ids / platform names stay untranslated.

## Hard rules

1. Same relative path under `zh/` and `en/`.  
2. `docs.json` nav sets equal after stripping `zh/` / `en/`.  
3. No cross-locale internal links (`zh` pages must not link to `/en/…` and vice versa).  
4. Social-data EN Response examples must include the same status set as ZH (**200 + 400/401/402/403/429/500/502**).  
5. Lint: `python3 scripts/check-i18n.py`.  
6. Do **not** reintroduce `cn/` content paths; only `redirects` sources may mention `/cn`.

## Out of scope

- Product app `web/src/i18n`.  
- Third locales (ja, zh-TW, …) without product decision.  
- Removing `/cn` redirects while external bookmarks still hit them.
