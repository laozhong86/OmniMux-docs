- Call `POST /v1/images/generations` with `model` `mj-v7` or `mj-v8-1`
- Every edit action rides in `model_params.operation`; omit it for plain generation
- The response is an async task; follow its id in the console usage logs

## Identity

| Field | Value |
| --- | --- |
| Series | Image series |
| Brand | Midjourney |
| Models | `mj-v7`, `mj-v8-1` |
| Billing dimension | per call |

The two model IDs are the two model versions. Actions are **not** separate model IDs — they are selected per request, so one integration covers the whole version.

## Endpoint

| Method | Path |
| --- | --- |
| `POST` | `/v1/images/generations` |

Base URL: `https://api.omnimux.ai`

## Authorizations

| Name | In | Type | Required | Description |
| --- | --- | --- | --- | --- |
| `Authorization` | header | string | yes | `Bearer sk-...` (API key) |

## Body

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `model` | string | yes | `mj-v7` or `mj-v8-1` |
| `prompt` | string | no | Image description, or the instruction for the selected action |
| `quality` | string | no | `standard` (default) or `hd` (**v8.1 only**, native HD) |
| `model_params.operation` | string | no | Action to run; omit for plain generation (4 images per task) |
| `model_params.task_id` | string | for actions | Source task id from a previous generation |
| `model_params.image_number` | integer | for actions | Which of the 4 generated images to use (`0`–`3`) |
| `image_urls` | array | some actions | Image URLs; used by `remove-bg`, `retexture`, `upload-paint` |
| `model_params.mask` | object | `inpaint` | Inpaint region — see **Inpaint** below |
| `model_params.speed` | string | no | `fast` (default), `draft`, or `turbo` |
| `model_params.type` | string | no | `upscale`: `standard` (default) or `creative`; `variation`/`remix`: `subtle` or `strong` |

### Actions

| `model_params.operation` | Source | Notes |
| --- | --- | --- |
| _(omitted)_ / `generate` | `prompt` | Plain generation, 4 images per task |
| `enhance`, `pan`, `outpaint` | `task_id` + `image_number` | Extend or refine an existing image |
| `remove-bg` | `image_urls` | Transparent-background cutout |
| `upscale` | `task_id` + `image_number` | `type: creative` adds artistic detail |
| `variation` | `task_id` + `image_number` | `type: subtle` / `strong` |
| `edit`, `remix`, `inpaint`, `retexture`, `upload-paint` | `task_id` + `image_number` | `inpaint` also needs `mask` |

An unknown `operation`, or a value we cannot price, is rejected with **400** instead of being silently downgraded — `variation`, `upscale` and `enhance` share one request shape, so guessing would run the wrong action and bill the wrong tier.

### Inpaint

Two mask forms are accepted upstream, but they do not behave the same on our route:

| Form | Shape | Status |
| --- | --- | --- |
| **Mask image** (use this) | `model_params.mask.url` — an image URL or `data:` URL, black = keep, white = regenerate | Works |
| Polygon | `model_params.mask.areas[]` (`width`, `height`, `points`) | Rejected upstream with `invalid_parameters: Image dimensions out of range` in our measurements (2026-09-13), including with the upstream documentation's own example coordinates |

Prefer the mask-image form. Measured example: a 1024×1024 black PNG with a white centred square, passed as a `data:image/png;base64,...` URL, completes.

## Pricing

Per call, `credits` column as shown in console pricing (1 USD = 10 credits):

| Base action | Price | Credits |
| --- | --- | --- |
| `generate`, `enhance`, `pan`, `outpaint`, `remove-bg` | USD 0.113446 | 1.134 |
| `upscale`, `variation`, `edit`, `inpaint`, `remix`, `retexture`, `upload-paint` | USD 0.170169 | 1.702 |

Multipliers apply on top of the action tier:

| Parameter | Multiplier |
| --- | --- |
| `quality: "hd"` (`mj-v8-1` only) | ×1.5 |
| `model_params.speed: "turbo"` | ×2 |
| `model_params.type: "creative"` (upscale) | ×4/3 |
| `model_params.speed: "draft"` / `"fast"`, `type: "standard"` | ×1 |

Example: `mj-v8-1` + `quality: "hd"` + `operation: "upscale"` + `type: "creative"` = 0.113446 × 1.5 × 1.5 × 4/3 = **USD 0.255251** per call. Billed actions return **402** when the account balance is insufficient.

## Response

### 200

| Field | Type | Description |
| --- | --- | --- |
| `created` | integer | Task creation timestamp |
| `id` | string | Async task id — poll it, or read the result in console usage logs |
| `model` | string | Upstream model that served the request (e.g. `mj-v8.1-upscale`) |
| `status` | string | `processing` while the task runs |
| `usage.billing_rule` | string | `per_call` |
| `usage.credits_reserved` | number | Upstream credits reserved for this task |
