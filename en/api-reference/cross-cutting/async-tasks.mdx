---
title: "Async tasks"
description: "How to poll task_id for image/video and related async APIs."
---

Some generation APIs **do not return the final asset in the create response**. They return a task id; you poll until completion.

## When async applies

| Capability | Create | Query (typical) |
| --- | --- | --- |
| Video | `POST /v1/video/generations`, `POST /v1/videos` | `GET /v1/video/generations/{task_id}`, `GET /v1/videos/{task_id}` |
| Image (async channels) | `POST /v1/images/generations` (channel-dependent) | `GET /v1/images/generations/{task_id}` or `GET /v1/images/tasks/{task_id}` |
| Social posts | `POST /api/social/v1/posts` | `GET /api/social/v1/posts/{id}` (OmniMux post id) |

Field names (`task_id` / `id` / `status`) follow each endpoint; full schemas are in the [OpenAPI appendix](/en/api-reference/appendix/openapi).

## Polling pattern

```text
1. Create → store task_id
2. GET every few seconds (respect rate limits)
3. Success → download/store URLs promptly
4. Failure → read error; stop looping
```

```bash
curl -sS "https://api.omnimux.ai/v1/videos/$TASK_ID" \
  -H "Authorization: Bearer $OMNIMUX_API_KEY"
```

## Auth

| Surface | Base | Credential |
| --- | --- | --- |
| AI image / video | `https://api.omnimux.ai` | `sk-` Bearer |
| Social post status | `https://omnimux.ai` | access token + `New-Api-User` |

## Notes

- Result URLs may expire  
- Status enums vary by channel  
- Some image channels are synchronous and return a URL immediately
