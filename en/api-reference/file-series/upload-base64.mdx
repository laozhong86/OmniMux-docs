> - Supports Data URL format (e.g. `data:image/png;base64,...`) and raw Base64 strings
> - Automatically detects MIME types for images, audio, video, or documents
> - Files automatically expire and are purged after **72 hours**
> - Limit of **2,000** active files per user; returns 429 when quota is exhausted
> - Auth: `Authorization: Bearer sk-...`

## Request Body

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `base64_data` | string | Yes | Base64-encoded file data or Data URL string |
| `upload_path` | string | No | Custom folder path (e.g. `avatars`, `covers`), auto-categorized by MIME if omitted |
| `file_name` | string | No | Custom file name (e.g. `avatar.png`), auto-generated if omitted |

## Using the returned URL

Use `file_url` or `download_url` from the **response** to access the uploaded file; do not reconstruct a storage URL. See [download isolation](/en/api-reference/file-series/download#uploaded-content-isolation-after-upgrade) for upgrade requirements. After the isolation update is deployed, unsafe or unverifiable public-storage settings reject uploads before a storage write.

## Request limits after upgrade

These limits apply after the upload request-limit update is deployed. Documentation publication does not confirm gateway production deployment. 1 MiB = 1,048,576 bytes. The file limit remains **100 MiB**. A stricter gateway or proxy limit still takes precedence; in particular, the existing global limit on the `/v1/files/upload/` aliases may reject a large Base64 request before it reaches this limit.

The JSON request budget is **140,858,712 bytes**: standard Base64 encoding of a 100 MiB file, plus 1 MiB for JSON metadata and encoding overhead. Decoded file data must not exceed 100 MiB. An over-limit declared body, a body whose parsing exceeds the budget, or over-limit decoded data returns **HTTP 413**. Malformed JSON or invalid Base64 remains **HTTP 400**.
