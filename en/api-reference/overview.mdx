OmniMux exposes **two primary surfaces**:

| Surface | Base URL | Credential | Typical use |
| --- | --- | --- | --- |
| **AI gateway** | `https://api.omnimux.ai` | `sk-` Bearer | Text / image / video / audio |
| **User APIs** | `https://omnimux.ai` | access token + `New-Api-User` | Social Ops, device login |

Console: [omnimux.ai/dashboard](https://omnimux.ai/dashboard) · Docs: [docs.omnimux.ai](https://docs.omnimux.ai)

## How to read this manual

Sidebar IA (Evolink-style discovery, grounded in OmniMux as a gateway):

```text
Series (language / image / video / audio)
  ├─ Brand / product-family guides (Claude, Nano Banana, Kling…)
  └─ Protocol try-it (shared /v1/* or channel-native paths)
Social Ops (separate user API)
Cross-cutting · Appendix
```

- **Brand pages**: pick a family, sample `model` ids, recommended protocols  
- **Protocol endpoints**: real HTTP contracts and try-it (many brands share one path; difference is `model`)  
- **Do not invent** competitor brand names not on this instance; brands follow pricing / `GET /v1/models`  

Coverage: [Documentation coverage](/en/api-reference/coverage).

## AI gateway auth

```http
Authorization: Bearer sk-xxxxxxxx
Content-Type: application/json
```

Typical OpenAI-compatible SDK Base URL: `https://api.omnimux.ai/v1`.

## Model IDs

```bash
curl https://api.omnimux.ai/v1/models \
  -H "Authorization: Bearer $OMNIMUX_API_KEY"
```

Example model names in docs are **not** availability guarantees.
