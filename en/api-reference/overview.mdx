OmniMux exposes **two primary surfaces** for integrators:

| Surface | Base URL | Credential | Typical use |
| --- | --- | --- | --- |
| **AI gateway** | `https://api.omnimux.ai` | `sk-` Bearer | Chat, image, video, audio, embeddings… |
| **User APIs** | `https://omnimux.ai` | access token + `New-Api-User` | Social Ops, device login, … |

Console: [omnimux.ai/dashboard](https://omnimux.ai/dashboard) · Docs: [docs.omnimux.ai](https://docs.omnimux.ai)

## AI gateway auth (quick)

```http
Authorization: Bearer sk-xxxxxxxx
Content-Type: application/json
```

Create keys under **Tokens / API Keys**. OpenAI-compatible SDKs usually use:

```text
https://api.omnimux.ai/v1
```

## Model IDs

Every request must use a `model` enabled for your account:

```bash
curl https://api.omnimux.ai/v1/models \
  -H "Authorization: Bearer $OMNIMUX_API_KEY"
```

Example names in docs are not proof of availability. See [Models](/en/guides/models).

## Errors

| HTTP | Likely cause |
| --- | --- |
| `401` | Missing/invalid Bearer, or mixing access token with `sk-` |
| `403` | Model not allowed on token, or IP restricted |
| `404` | Wrong path, or extra/missing `/v1` relative to the client |
| `429` | Rate limited |
| Quota errors | Account or token quota exhausted |
