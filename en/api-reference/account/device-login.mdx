---
title: "Device login"
description: "Exchange a device_code for a user access token (RFC 8628-style) for CLI and integrators."
---

Device login lets the **OmniMux CLI** (`omnimux login`) or your own client obtain a **user access token** without embedding passwords.  
Use that token for [Social Ops](/en/api-reference/social-ops) and other user APIs — **not** as an AI gateway `sk-` key.

## Base URL

```text
https://omnimux.ai
```

## Flow

```text
1. POST /api/user/device/code     → device_code + user_code + verification URL
2. User opens verification_uri in a browser (must be signed in to the console)
3. Client polls POST /api/user/device/token
4. On approval: access_token + user_id
```

## POST /api/user/device/code

Create a device/user code pair. **No auth required.**

```bash
curl -sS -X POST https://omnimux.ai/api/user/device/code \
  -H "Content-Type: application/json" \
  -d '{"client_name":"my-cli"}'
```

| Field | Notes |
| --- | --- |
| `client_name` | Optional device label |

Success `data` includes `device_code`, `user_code`, `verification_uri`, `verification_uri_complete`, `expires_in`, `interval`.

## POST /api/user/device/token

Exchange `device_code` for an access token. **No auth.** Returns pending until the user approves.

```bash
curl -sS -X POST https://omnimux.ai/api/user/device/token \
  -H "Content-Type: application/json" \
  -d '{
    "device_code": "'"$DEVICE_CODE"'",
    "grant_type": "urn:ietf:params:oauth:grant-type:device_code"
  }'
```

Respect `interval` when polling. On success, call user APIs with:

```http
Authorization: Bearer <access_token>
New-Api-User: <user_id>
```

## POST /api/user/device/approve · deny

Used by the **signed-in browser** confirmation page (`https://omnimux.ai/cli/login`).  
Integrators usually only need to open `verification_uri` for the user.

## CLI

| Step | CLI |
| --- | --- |
| Full flow | `omnimux login` |
| Print URL only | `omnimux login --no-open` |

## Security

- Never log or display `device_code` to end users; show `user_code` / verification link only  
- Access tokens are not `sk-` keys; rotate if leaked  
- Restart from `device/code` after expiry
