- Create: `POST /v1/videos` with `model` `minimax-h3-video`
- Async: poll `GET /v1/videos/{task_id}` with the task id from the create response (`id` / `task_id`); it returns `status` and `progress`
- One public ID selects its endpoint from the request shape; when nothing matches, the gateway returns `400` instead of silently falling back to another shape or tier
- Persist result URLs promptly (upstream links may expire)

> This model runs on a plugin line, so its public paths are `POST /v1/videos` and `GET /v1/videos/{task_id}` — **not** the `/v1/video/generations` path used by the other video series pages. The wrong path never reaches the plugin and returns `503` (no available channel under that group).

## Groups and tiers

`minimax-h3-video` keeps one public model ID; the tier is chosen per request through a group and never creates a new model ID:

| Tier | Group | Multiplier | Shapes served |
| --- | --- | --- | --- |
| Standard (default) | No group specified (`default` routing) | 1.0× | Text-to-video, image reference, image + audio, lip sync, first-last frame |
| Fast | `minimax-h3-video-fast` | 0.9× | Image reference, image + audio |
| Higher quality | `minimax-h3-video-pro` | 1.15× | Image reference, image + audio |

Use either spelling; the header takes precedence over the `model` suffix:

```bash cURL
curl --request POST \
  --url https://api.omnimux.ai/v1/videos \
  --header 'Authorization: Bearer <token>' \
  --header 'Content-Type: application/json' \
  --header 'X-Omnimux-Group: minimax-h3-video-fast' \
  --data '{
  "model": "minimax-h3-video",
  "prompt": "slow pan across a product on a table",
  "resolution": "768p",
  "duration": 5
}'
```

```json
{
  "model": "minimax-h3-video@minimax-h3-video-pro",
  "prompt": "slow pan across a product on a table",
  "resolution": "768p",
  "duration": 5
}
```

- Group selection is request-scoped and does not create a new model ID; a group your key cannot use returns `403`.
- The fast and higher-quality tiers are not part of default routing, so they must be selected explicitly. They serve image reference and image + audio only, and cap at `768p`. Use the standard tier for the other shapes.

## Request shapes and endpoint selection

The gateway derives the shape from which media slots the request fills, then picks the lowest-cost endpoint in the selected tier that serves it. **When nothing matches it returns `400`** rather than falling back to another shape, resolution or tier.

| Shape | Request signature | Media limits |
| --- | --- | --- |
| First-last frame | `first_frame` + `last_frame` | 1 image each |
| Lip sync | Reference image + reference audio and **no** `prompt` | Uses the first image and the first audio |
| Image + audio | Reference images + reference audios | ≤ 9 images, ≤ 3 audios |
| Image reference | Reference images only | ≤ 9 images |
| Text-to-video | `prompt` only, no media | — |

Shape priority, highest first: first-last frame → lip sync → image + audio → image reference → text-to-video. A reference video (`ref_video` / `video`) is not a shape this ID serves; sending one matches no endpoint and returns `400`.

## Body

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `model` | string | yes | `minimax-h3-video`, optionally with an `@group` suffix |
| `prompt` | string | conditional | Required for text-to-video, image reference, image + audio and first-last frame; omit it for lip sync (sending it routes as image + audio) |
| `duration` / `seconds` | integer | no | Video duration in seconds, 1–15, default 5; some shapes cap at 10 or 12 seconds |
| `resolution` / `size` | string | no | Billing tier labels only: `480p`, `736p`, `768p`, `1088p` or `1440p`; without an orientation the gateway maps it to the vertical variant internally. `1088p` / `1440p` exist only on the six endpoints that support them |
| `ref_image` / `image` / `images` | string or array | conditional | Reference images, up to 9 |
| `ref_image_0` … `ref_image_8` | string | conditional | Numbered image slots (use one spelling, not both) |
| `ref_audio` / `audio` / `audios` | string or array | conditional | Reference audios, up to 3 |
| `ref_audio_0` … `ref_audio_2` | string | conditional | Numbered audio slots (use one spelling, not both) |
| `first_frame` / `last_frame` | string | conditional | The two images of the first-last frame shape |
| `mode` | string | no | `高速模式` or `高质模式`, default `高质模式`; only the nine-image and nine-image-three-audio endpoints honour it |
| `seed` | integer | no | Random seed |

- Use one spelling per media kind: mixing array and numbered slots merges both sets instead of picking one.
- `resolution` accepts billing tier labels only (`480p` / `736p` / `768p` / `1088p` / `1440p`). Upstream orientation labels such as `480p竖(480*864)` are mapped by the gateway internally; sending one returns `400` (`plugin_usage_invalid`).
- `1088p` / `1440p` have candidates only on the endpoints that support them: on the fast and higher-quality tiers (one endpoint each, neither offering these tiers) the request returns `400` instead of falling back across tiers.
- The tier that is still not offered (upstream `1080p`) is rejected explicitly too: sending one returns `400` (`plugin_usage_invalid`), and it is never silently downgraded to `768p` or billed as `768p`.

## Resolution and duration limits

| Item | Available range | Notes |
| --- | --- | --- |
| Resolution | `480p`, `736p`, `768p`, `1088p`, `1440p` | Billing tier labels only; `1088p` / `1440p` have been offered since 2026-10-24 on the six standard-tier endpoints and carry their own per-second price; upstream `1080p` is still **not offered** and returns `400` (`plugin_usage_invalid`) |
| Duration | 1–15 seconds (default 5) | Some shapes cap at 10 or 12 seconds; exceeding the cap returns `400` and is never shortened automatically |
| Resolution × shape | `736p` is supported by some shapes only | A combination with no candidate returns `400` |

## Billing

- Base price: `0.025 USD/second` for `480p` / `736p` / `768p` (¥0.17/second at FX 6.8)
- Per-resolution rates: `1088p` is `0.030 USD/second` (¥0.204/second) and `1440p` is `0.035 USD/second` (¥0.238/second)
- Tier multipliers: standard `1.0×`, fast `0.9×`, higher quality `1.15×`
- Formula: `raw_quota = rate(resolution) × 500000 × seconds × GroupRatio`; the resolution rate is selected from the request's `resolution` by the task billing expression
- Conversion: `raw_quota ÷ 500000 = USD`, and **1 USD = 10 credits**

For `768p` / 5 seconds / standard: `0.025 × 500000 × 5 × 1.0 = 62,500` raw quota ≈ `$0.125` ≈ `¥0.85`; for `1440p` / 5 seconds / standard: `0.035 × 500000 × 5 × 1.0 = 87,500` raw quota ≈ `$0.175` ≈ `¥1.19`. Billing follows the requested duration; the public pricing endpoint and the pre-submission quote remain authoritative for any individual request.

### 200 (poll)

`GET /v1/videos/{task_id}` returns `status` and `progress`; the field structure follows the live contract.

### Error semantics

| Status | Meaning |
| --- | --- |
| `400` | Invalid body, or no matching shape / resolution / duration combination (including a resolution that is not offered, an upstream orientation label, a duration above the cap, or an unsupported shape such as `ref_video`) |
| `401` | Invalid API key |
| `402` | Insufficient quota (`insufficient_quota`) |
| `403` | Key not allowed to use the selected group, or model not allowed |
| `429` | Rate limited |
| `500` | Gateway or upstream error |
| `503` | No available channel for the path or group (for example the plugin line called through `/v1/video/generations`) |

A `400` message lists the shapes and resolution / duration combinations the selected tier supports, so the request can be corrected directly.

More error semantics: [Connection and usage](/en/faqs/connection-usage) and [Cost optimization](/en/faqs/cost-optimization).
