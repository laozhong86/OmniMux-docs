Every target account must belong to the requested source. An idempotent replay also verifies the stored source and account set; conflicts return 409.

Call [Media Presign](/en/api-reference/publishing/presign) and upload the file. Set `media_items[].url` to the returned `public_url`. Submit the post only after the upload succeeds and the object is readable.

After validation, the gateway submits the request to TikTok immediately. It selects the mode from the account's publishing capabilities.

| Account capability | Behavior |
| --- | --- |
| `video.upload` only (currently approved) | **Draft upload** sends either **one video** (`/v2/post/publish/inbox/video/init/`) or a **photo carousel** (`/v2/post/publish/content/init/`, `post_mode: "MEDIA_UPLOAD"`) to the creator's TikTok inbox for editing and posting in TikTok. Video drafts ignore `content` and `tiktok_options`. Photo drafts accept optional `tiktok_options.title`, `tiktok_options.description` (falls back to `content`), `tiktok_options.photo_cover_index` (0-based integer, `0` preserved), and `tiktok_options.is_aigc` (boolean, `false` preserved), and never forward Direct Post privacy, interaction, or commercial disclosure fields |
| `video.publish` (separate review required) | **Direct Post** takes precedence when both scopes are present. It supports one video or a photo carousel with privacy, interaction, and disclosure settings in `tiktok_options` |

Photo carousel rules for `tiktok_direct`:
- **Format:** JPEG or WebP only (PNG, GIF, and undeclared image formats are rejected).
- **No mixed media:** do not combine photos and videos in the same `media_items` array.
- **Count limit:** 1 to 35 images per post on hosted OmniMux (matching the TikTok Photo API protocol maximum; self-hosted deployments default to 10 items per request and can be configured up to 35).
- **Verified-domain delivery:** every image URL is wrapped through the gateway's signed verified-domain media proxy before calling TikTok.
- **Metadata fields:** pass `title`, `description`, `photo_cover_index` (0-based; must be less than the image count), and `is_aigc` inside `tiktok_options` (top-level fields of the same names are also accepted for compatibility, with `tiktok_options` taking precedence).

Capabilities are evaluated strictly from the OAuth scopes actually granted to the account (fail-closed): an account without `video.upload` or `video.publish` returns 409 `SOCIAL_TIKTOK_SCOPE_MISSING`. A newly created post starts as `submitted`. When [Get Post](/en/api-reference/publishing/get-post) refreshes the status, the gateway maps TikTok's `SEND_TO_USER_INBOX` to non-terminal `sent_to_inbox` (keeping `processing` for transfer/encoding states) and `PUBLISH_COMPLETE` to `published`.

`provider` is required and has one current value, `tiktok_direct`. A retired source identifier returns 410 `provider-retired`; missing or unknown values return 400 `invalid-provider`.

### Structured TikTok upstream errors

When TikTok returns an upstream business error or rate limit, the gateway returns a structured JSON body (`success: false`, `code`, `message`, plus sanitized `upstream_code` and `upstream_log_id` when supplied by TikTok) with a non-401/403 HTTP status so TikTok token errors are never confused with OmniMux session failures:

| HTTP | `code` | Typical `upstream_code` | Recommended action |
| --- | --- | --- | --- |
| `429` | `SOCIAL_TIKTOK_RATE_LIMITED` | `rate_limit_exceeded` | Retry with backoff; do not reconnect |
| `409` | `SOCIAL_TIKTOK_POSTING_BANNED` | `spam_risk_user_banned_from_posting` | Account is banned from posting on TikTok; stop retrying |
| `409` | `SOCIAL_TIKTOK_PUBLISH_RESTRICTED` | `spam_risk_too_many_posts`, `reached_active_user_cap`, `spam_risk_too_many_pending_share`, `unaudited_client_can_only_post_to_private_accounts`, `url_ownership_unverified` | Account posting cap, pending inbox cap, or app visibility/domain restriction |
| `409` | `SOCIAL_TIKTOK_SCOPE_MISSING` | `scope_not_authorized` | Required publishing scope missing; reconnect the account |
| `409` | `SOCIAL_TIKTOK_TOKEN_INVALID` | `access_token_invalid`, `token_expired`, `token_revoked`, `invalid_grant`, `refresh_token_invalid` | TikTok OAuth token expired or revoked; reconnect the account |
| `502` | `SOCIAL_TIKTOK_UPSTREAM_ERROR` | Other TikTok upstream error codes | Log `upstream_log_id` and retry later |

CLI: `omnimux social post --provider tiktok_direct --accounts <account-id> --media <url> --title "Draft title" --photo-cover-index 0 --is-aigc=false` (supports `--description`, `--tiktok-options '<json>'`, and compliance flags). Passing a retired `--provider` value fails locally in the CLI before any network request.

Use an OmniMux user access token and `New-Api-User`, not an `sk-` key. Inspect both HTTP status and `success` (structured TikTok upstream errors return 409/429/502, while generic failures may still return HTTP 200 with `success: false`).
