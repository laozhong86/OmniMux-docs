Every target account must belong to the requested source. An idempotent replay also verifies the stored source and account set; conflicts return 409.

Call [Media Presign](/en/api-reference/publishing/presign) and upload the file. Set `media_items[].url` to the returned `public_url`. Submit the post only after the upload succeeds and the object is readable.

After validation, the gateway submits the request to TikTok immediately. It selects the mode from the account's publishing capabilities.

| Account capability | Behavior |
| --- | --- |
| `video.upload` only (currently approved) | **Draft upload** sends one video to the creator's TikTok inbox for editing and posting in TikTok. Draft mode ignores `content` and `tiktok_options` |
| `video.publish` (separate review required) | **Direct Post** takes precedence when both scopes are present. It supports video and photo posts with privacy and interaction settings in `tiktok_options` |

An account without either publishing scope returns 409 `SOCIAL_TIKTOK_SCOPE_MISSING`. A newly created post starts as `submitted`. When [Get Post](/en/api-reference/publishing/get-post) refreshes the status, the gateway maps TikTok's `SEND_TO_USER_INBOX` to `processing` and `PUBLISH_COMPLETE` to `published`.

`provider` is required and has one current value, `tiktok_direct`. A retired source identifier returns 410 `provider-retired`; missing or unknown values return 400 `invalid-provider`.

Use an OmniMux user access token and `New-Api-User`, not an `sk-` key. Inspect `success` as well as HTTP status; some upstream failures return HTTP 200 with `success:false`.
