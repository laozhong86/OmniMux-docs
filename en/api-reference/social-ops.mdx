---
title: "Social Ops"
description: "Connect accounts, upload media, and publish posts. Not model-square APIs; use a user access token, not an sk- relay key."
---

Social Ops exposes multi-platform social publishing (upstream Zernio) as a **user API**. There is no full console bind UI yet, but the **HTTP API is available to signed-in users**. The [OmniMux CLI](https://github.com/laozhong86/omnimux-cli) `omnimux social *` commands call the same endpoints.

You do **not** configure models for this surface, and you must **not** call these paths with an `sk-` gateway token.

## Base URL

```text
https://omnimux.ai
```

Path prefix: `/api/social/v1`.  
This is **not** the AI gateway base `https://api.omnimux.ai/v1`.

The instance must have Social Ops enabled. Probe first:

```bash
curl -sS https://omnimux.ai/api/social/v1/status
```

## Authentication

Use a **user access token** (same class as `omnimux login` / console system access token) plus the user id:

```http
Authorization: Bearer <access_token>
New-Api-User: <user_id>
Content-Type: application/json
```

| Credential | Use for |
| --- | --- |
| access token + `New-Api-User` | Social Ops and console user APIs |
| `sk-...` | AI gateway `/v1/...` only (chat, images, video, …) |

How to get an access token:

1. CLI: `omnimux login` (stored in Keychain / local secrets)
2. Console system access token, when offered by the product UI

## Endpoints

| Method | Path | Auth | Purpose |
| --- | --- | --- | --- |
| `GET` | `/api/social/v1/status` | No | Feature flag / platforms |
| `GET` | `/api/social/v1/accounts` | Yes | Connected accounts for the caller |
| `POST` | `/api/social/v1/connect` | Yes | OAuth start URL |
| `DELETE` | `/api/social/v1/accounts/{id}` | Yes | Disconnect |
| `POST` | `/api/social/v1/media/presign` | Yes | Presigned media upload |
| `POST` | `/api/social/v1/posts` | Yes | Create / schedule post |
| `GET` | `/api/social/v1/posts/{id}` | Yes | Post status |

Response envelope:

```json
{ "success": true, "message": "", "data": { } }
```

Failures use `success: false` and may include a `code` such as `SOCIAL_OPS_DISABLED`, `SOCIAL_ACCOUNT_DENIED`, or `SOCIAL_MEDIA_INVALID`.

## GET /api/social/v1/status

```bash
curl -sS https://omnimux.ai/api/social/v1/status
```

| Field | Meaning |
| --- | --- |
| `enabled` | Feature on/off |
| `upstream_ready` | Upstream key configured |
| `platforms` | Allowed platforms (e.g. `tiktok`) |
| `provider` | Upstream id (`zernio`) |
| `billing_mode` | Often `off` (audit only) |

## GET /api/social/v1/accounts

Lists **your** active connected accounts (synced from upstream).

```bash
curl -sS https://omnimux.ai/api/social/v1/accounts \
  -H "Authorization: Bearer $OMNIMUX_ACCESS_TOKEN" \
  -H "New-Api-User: $OMNIMUX_USER_ID"
```

`data.accounts[]`: `id`, `platform`, `username`, `display_name`, `status`.

---

## POST /api/social/v1/connect

Starts platform OAuth and returns a browser URL.

```bash
curl -sS -X POST https://omnimux.ai/api/social/v1/connect \
  -H "Authorization: Bearer $OMNIMUX_ACCESS_TOKEN" \
  -H "New-Api-User: $OMNIMUX_USER_ID" \
  -H "Content-Type: application/json" \
  -d '{"platform":"tiktok","redirect_url":"https://omnimux.ai/"}'
```

| Field | Required | Notes |
| --- | --- | --- |
| `platform` | Yes | From `status.platforms`; `x` normalizes to `twitter` |
| `redirect_url` | No | HTTPS landing URL; host must match policy |

`data.auth_url` — open in a browser. Then call `GET /accounts`.

## DELETE /api/social/v1/accounts/\{id\}

Disconnect an account owned by the caller (`id` is the OmniMux account id).

```bash
curl -sS -X DELETE "https://omnimux.ai/api/social/v1/accounts/1" \
  -H "Authorization: Bearer $OMNIMUX_ACCESS_TOKEN" \
  -H "New-Api-User: $OMNIMUX_USER_ID"
```

## POST /api/social/v1/media/presign

Get a presigned upload URL. **PUT the file to `upload_url` yourself**, then use `public_url` in posts.

```bash
curl -sS -X POST https://omnimux.ai/api/social/v1/media/presign \
  -H "Authorization: Bearer $OMNIMUX_ACCESS_TOKEN" \
  -H "New-Api-User: $OMNIMUX_USER_ID" \
  -H "Content-Type: application/json" \
  -d '{"filename":"clip.mp4","content_type":"video/mp4","size_bytes":1234567}'
```

| Field | Required | Notes |
| --- | --- | --- |
| `filename` | Yes | File name |
| `content_type` | Yes | e.g. `image/png`, `video/mp4` (allow-listed MIME) |
| `size_bytes` | No | Size in bytes |

Then:

```bash
curl -sS -X PUT "$UPLOAD_URL" \
  -H "Content-Type: video/mp4" \
  --data-binary @./clip.mp4
```

## POST /api/social/v1/posts

Create or schedule a post. Only **your** `account_ids` are accepted.

```bash
curl -sS -X POST https://omnimux.ai/api/social/v1/posts \
  -H "Authorization: Bearer $OMNIMUX_ACCESS_TOKEN" \
  -H "New-Api-User: $OMNIMUX_USER_ID" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $(uuidgen)" \
  -d '{
    "content": "Hello from OmniMux",
    "account_ids": [1],
    "publish_now": true,
    "media_items": [{ "url": "https://media.example.com/a.png" }]
  }'
```

| Field | Required | Notes |
| --- | --- | --- |
| `account_ids` | Yes | OmniMux account ids |
| `content` | One of content/media | Caption |
| `media_items` | One of content/media | `[{ "url": "…", "type": "image\|video" }]` |
| `publish_now` | No | Immediate unless `scheduled_for` is set |
| `scheduled_for` | No | ISO-8601 |
| `timezone` | No | Time zone |
| `queued` | No | Upstream queue when enabled |

Idempotency: `Idempotency-Key` or `X-Idempotency-Key`.

## GET /api/social/v1/posts/\{id\}

Fetch post status for the caller. Default `refresh=1` may refresh from upstream.

```bash
curl -sS "https://omnimux.ai/api/social/v1/posts/1" \
  -H "Authorization: Bearer $OMNIMUX_ACCESS_TOKEN" \
  -H "New-Api-User: $OMNIMUX_USER_ID"
```

## CLI mapping

| CLI | API |
| --- | --- |
| `omnimux social status` | `GET …/status` |
| `omnimux social accounts` | `GET …/accounts` |
| `omnimux social connect --platform tiktok` | `POST …/connect` |
| `omnimux social disconnect <id>` | `DELETE …/accounts/{id}` |
| `omnimux social media upload <path>` | presign + local PUT |
| `omnimux social post --accounts …` | `POST …/posts` |
| `omnimux social post-status <id>` | `GET …/posts/{id}` |

Releases: [omnimux-cli](https://github.com/laozhong86/omnimux-cli/releases).

## vs AI gateway

| | Social Ops | AI gateway |

| Path | `/api/social/v1/...` | `/v1/...` |
| Credential | access token + `New-Api-User` | `sk-` |
| Model name | Not used | Required |
