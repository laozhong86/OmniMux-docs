## OpenAI-compatible?

Primary text path follows **OpenAI Chat Completions**. Point clients at `https://api.omnimux.ai/v1` with an OmniMux `sk-` and live model ids. See [language complete reference](/en/api-reference/text-series/claude/complete).

## Modalities

Live catalog only: language / image / video, plus social-data (read) and publishing (write, different auth).

## Why not identical to ChatGPT/Claude websites?

APIs expose model capability, not each vendor’s product shell (browsing, memory UI, built-in tools). Manage context, system prompts, and tools yourself.

## Video tasks

Create: `POST /v1/video/generations`  
Poll: `GET /v1/video/generations/{task_id}`  
Do not confuse with `/v1/videos/{id}/content` download.

### Reference-video checks in the character workbench

<Note>
These checks apply to the character workbench's reference-video preparation, not to every request on the generic video API paths above.

The workbench fully decodes the actual reference video and any audio in a safety-isolated environment before generation, rather than trusting a filename, browser metadata, or caller-provided duration. The complete original reference must be **4 to 30 seconds**, inclusive. An overlong video or audio tail is rejected, not trimmed or sped up. A submitted integer duration must match the rounded actual duration.

AAC audio permits container timing rounding of at most **one sample per block**, only while the timeline stays continuous and cumulative drift stays within **one sample**. Larger discrepancies, gaps and overlaps remain invalid. At the end, the container's stated length and encoder padding constrain the same audio block: their intersection determines the playable span, counted once rather than shortened twice. These timing rules do not trim real content or relax the 30-second ceiling.

The reference clip's own aspect ratio is **input metadata**, separate from the output framing of the generated video: a reference clip does not have to match one specific ratio. Motion transfer exposes **Frame** as an independent output setting; object swap must preserve the reference framing, so the clip's own ratio must be a standard value the bound line can produce (480p: 16:9, 9:16, 3:4 — 720p: 16:9, 9:16). A non-standard clip can drive motion transfer but cannot be framing-preserved for object swap, and the form says so instead of claiming the input is unsupported. The workbench never crops, stretches, or letterboxes the clip silently.

The intake ceiling remains **100 MiB (104857600 bytes)**. This workbench ceiling is not a confirmed limit for every supplier option: their complete input-size, format, frame-rate, and resolution contracts remain unverified. A valid small file does not need compression. Automatic compression is not enabled; arbitrary large files and universal format compatibility are not promised. The workbench supports a complete single-video-stream MP4/MOV with H.264/H.265 and supported audio; ambiguous timelines or unsupported media can be rejected.

Generation uses a server-prepared copy of the same validated video bytes, without transcoding. The full embedded audio stays in the video. A separate optional audio reference is attached only when it can be extracted in full from a short reference of at most **15 seconds**; longer references are not replaced with a shortened audio attachment. This does not guarantee reproduction of every original sound or word.

Media-preparation rejection happens **before generation billing**. Invalid media receives `400 reference_video_invalid`; a mismatched duration or a non-preservable object-swap framing receives `400 invalid_request`. Cancellation or a media-check timeout receives `408 reference_video_invalid`; busy preparation or temporarily unavailable checking, storage, or download receives `503 reference_video_invalid`. Errors use safe messages and do not expose signed media URLs or raw diagnostic details. These are media-preparation rules, not a promise that all later generation failures are free.

Uploads keep the original filename, including spaces or `#`, without requiring you to rename a valid file. Upload and preparation errors show the safe reason returned by the service rather than automatically suggesting a smaller file. If the actual duration exceeds 30 seconds, generation does not start and the message explains that the video will not be shortened automatically. File and media checks still apply.
</Note>

### Browser transfers

The character workbench's R2 direct uploads and stored-artifact downloads are live as of October 12, 2026. Reference uploads use the existing ticket → original File PUT → confirmation sequence, with only a documented 501 capability refusal falling back to multipart. See [upload rules](/en/api-reference/file-series/upload-stream). R2 HEAD confirmation checks size and type metadata; it does not replace the actual reference-media checks above.

Browser task previews/downloads can request direct delivery on recognized task-content URLs; downloads also request attachment on the final R2 response. Canonical references sent to models retain byte serving. Initial upstream collection and reference preparation still use the server. The current bucket is link-readable, not private, and signed URLs do not guarantee immediate revocation. See [delivery and access boundaries](/en/api-reference/file-series/download). Production browser acceptance covered direct image/video uploads, saved image/video attachments, and video playback and seeking. No comparative speed measurement is claimed.

## Can I use a style reference when creating an influencer?

The **Create influencer** flow accepts one optional **JPEG, PNG or WebP** style-reference image, up to **5 MiB (5,242,880 bytes)**. This is a limit for that website flow, not a new limit for public image-generation APIs.

The reference guides silhouette, styling, colors, clothing and overall mood. It does **not** lock the person's identity: the result may be a new character or a different person. When inputs conflict, **explicit description takes priority over selected traits, and selected traits take priority over image inspiration**. The selected exaggeration level still applies.

A reference image alone is valid, without a description or selected traits. This path requests **one full-body character on a plain white background**, not a copy of the reference background, text or logos. Checks covering image-only input, an image with text and traits, and the same text and traits without an image all completed successfully. These results do not guarantee success on every request. Other modes, including multi-view output, are not promised by this note.

`/pg/influencer/sheet` is an internal website-session path, not a public gateway Bearer (`sk-`) or `/v1` API. This change does **not** add or change any public generation endpoint's request shape. For integrations, continue to use the existing [GPT Image generation contract](/en/api-reference/image-series/gpt-image/generate).
