## OpenAI-compatible?

Primary text path follows **OpenAI Chat Completions**. Point clients at `https://api.omnimux.ai/v1` with an OmniMux `sk-` and live model ids. See [language complete reference](/en/api-reference/text-series/claude/complete).

## Modalities

Live catalog only: language / image / video, plus social-data (read) and publishing (write, different auth).

## Why not identical to ChatGPT/Claude websites?

APIs expose model capability, not each vendor’s product shell (browsing, memory UI, built-in tools). Manage context, system prompts, and tools yourself.

## Video tasks

Create: `POST /v1/video/generations`  
Poll: `GET /v1/video/generations/{task_id}`  
Do not confuse with `/v1/videos/{id}/content` download.

### Reference-video checks in the character workbench

<Note>
These checks apply to the character workbench's reference-video preparation, not to every request on the generic video API paths above. The workbench currently accepts **one reference video**; the model's multi-video allowance does not add a multi-video website feature.
</Note>

The workbench checks the actual media on the server before generation. A valid reference does not have to match an output ratio such as 16:9 or 9:16. All of the following requirements must hold:

| Input | Accepted range |
| --- | --- |
| Container and video codec | MP4 or MOV, with H.264/AVC or H.265/HEVC |
| Embedded audio, if present | MP4: AAC or MP3; MOV: AAC, MP3 or PCM |
| File size | At most **200 MiB (209,715,200 bytes)** |
| Clip duration | Motion transfer: **2–30 seconds**; object swap / original-video editing: **4–30 seconds** |
| Display aspect ratio, width ÷ height | **0.4–2.5**, inclusive; this is a continuous range, not a fixed list |
| Width and height | Each **300–6000 pixels** |
| Total pixels, width × height | **407,696–8,295,044** |
| Frame rate | **24–60 frames per second** |

For example, 5:4, 1:1, 4:3 and 21:9 can be valid reference ratios when the other requirements are also met. The workbench uses an explicit byte ceiling; a file's displayed “MB” value may use another unit.

Reference input and generated output are separate. In **motion transfer**, the source may be shorter than the generated video; the independently selected output duration remains **4–30 seconds**. Output framing remains limited to the choices shown for the selected resolution (480p: 16:9, 9:16, 3:4; 720p: 16:9, 9:16). In **object swap**, the request uses original-video editing with automatic source framing and duration, rather than forcing the source into one of those ordinary output choices. This is a generation request, not a guarantee that every scene, face or sound will be reproduced exactly. The workbench does not silently crop, stretch, letterbox, trim, speed up, or switch creation modes to make an input fit.

Browser playback or metadata-reading failure alone does not make a reference invalid: the server checks it. The Desert Duo preset uses its corresponding full-resolution reference for generation while its card retains a lightweight preview. A failed candidate check preserves the last valid selection. Specific upload, preparation or service problems appear in the workbench's **top notification**, rather than as persistent red text in the reference area. A temporary service failure offers a retry and does not label a valid aspect ratio as unsupported.

`POST /pg/influencer/motion/inspect` is an internal, signed-in website-session preflight. It checks the reference without calling the generation model or charging generation quota. It is **not** a public gateway Bearer (`sk-`) or `/v1` integration endpoint. Generation validates the media again; a successful preflight is not proof that a later generation will complete.

The complete original video and any audio are decoded in a safety-isolated environment, rather than trusting a filename or caller-provided duration. Overlong video or audio tails are rejected, not shortened. Invalid or ambiguous timelines remain invalid. AAC permits only bounded container timing rounding: no more than one sample per block, a continuous timeline, and no more than one sample of cumulative drift. Container tail length and encoder padding constrain the same playable span and are counted once.

Generation uses a server-prepared copy of the validated bytes without transcoding, retaining the full embedded audio. A separate optional audio reference is attached only when it can be extracted in full from a reference no longer than **15 seconds**. Longer references are not replaced with a shortened audio attachment. This does not guarantee reproduction of every original sound or word.

Media-preparation rejection happens **before generation billing**. Invalid media checks return a safe `400 reference_video_invalid`; invalid request settings, including mode, output choices or editing-specific preparation, can return `400 invalid_request`. Cancellation or a media-check timeout receives `408 reference_video_invalid`; busy preparation or temporarily unavailable checking, storage, or download receives `503 reference_video_invalid`. Safe messages do not expose signed media URLs or raw diagnostics. These preparation rules do not promise that every later generation failure is free.

Uploads keep the original filename, including spaces or `#`. A valid file does not need compression or renaming. Automatic compression and conversion of unsupported formats are not enabled. File ownership, expiry, download limits and media checks still apply.

### Browser transfers

The character workbench's R2 direct uploads and stored-artifact downloads are live as of October 12, 2026. Reference uploads use the existing ticket → original File PUT → confirmation sequence, with only a documented 501 capability refusal falling back to multipart. See [upload rules](/en/api-reference/file-series/upload-stream). R2 HEAD confirmation checks size and type metadata; it does not replace the actual reference-media checks above.

Browser task previews/downloads can request direct delivery on recognized task-content URLs; downloads also request attachment on the final R2 response. Canonical references sent to models retain byte serving. Initial upstream collection and reference preparation still use the server. The current bucket is link-readable, not private, and signed URLs do not guarantee immediate revocation. See [delivery and access boundaries](/en/api-reference/file-series/download). Production browser acceptance covered direct image/video uploads, saved image/video attachments, and video playback and seeking. No comparative speed measurement is claimed.

## Can I use a style reference when creating an influencer?

The **Create influencer** flow accepts one optional **JPEG, PNG or WebP** style-reference image, up to **5 MiB (5,242,880 bytes)**. This is a limit for that website flow, not a new limit for public image-generation APIs.

The reference guides silhouette, styling, colors, clothing and overall mood. It does **not** lock the person's identity: the result may be a new character or a different person. When inputs conflict, **explicit description takes priority over selected traits, and selected traits take priority over image inspiration**. The selected exaggeration level still applies.

A reference image alone is valid, without a description or selected traits. This path requests **one full-body character on a plain white background**, not a copy of the reference background, text or logos. Checks covering image-only input, an image with text and traits, and the same text and traits without an image all completed successfully. These results do not guarantee success on every request. Other modes, including multi-view output, are not promised by this note.

`/pg/influencer/sheet` is an internal website-session path, not a public gateway Bearer (`sk-`) or `/v1` API. This change does **not** add or change any public generation endpoint's request shape. For integrations, continue to use the existing [GPT Image generation contract](/en/api-reference/image-series/gpt-image/generate).
