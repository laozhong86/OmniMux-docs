## Wrong Base URL?

| Surface | Base |
| --- | --- |
| AI gateway / social data (`sk-`) | `https://api.omnimux.ai` or `https://api.omnimux.ai/v1` |
| Publishing / device-login user APIs | `https://omnimux.ai` (`Authorization: Bearer <access_token>`) |

Do not mix the two credential surfaces. The [scoped personal-token release draft](/en/faqs/security) is not a deployment announcement. In that candidate, `nap_...` grants only selected user-API permissions. Older examples may retain `New-Api-User` for compatibility, but it does not participate in authentication or select the user.

## 401 / 403 / 402 / 429

| Status | Typical cause |
| --- | --- |
| **401** | Missing/invalid Bearer token |
| **403** | Model or group not allowed for this token |
| **402** | Insufficient quota on pre-consume |
| **429** | Rate limited |

### Personal-token recovery — release draft

An expired or revoked personal token cannot be repaired by changing headers. Sign in in the browser to create a replacement, or run device login again for a device token. A legacy single token stops working at the shared 30-day transition deadline; clients must sign in again, not retry indefinitely.

For a permission denial, inspect the response `code`: `ACCESS_TOKEN_SCOPE_DENIED` means the required permission is missing, `AUTH_SESSION_REQUIRED` requires a browser session, and `ACCESS_TOKEN_ROUTE_UNDECLARED` means that route is not available to personal tokens. Security verification does not bypass these restrictions. For publishing, `social:read` covers queries and `social:write` covers connecting, publishing, media uploads, and syncing. The complete user-facing permission guide is in [Security and keys](/en/faqs/security).

## Account quota errors on OpenAI text endpoints

`POST /v1/completions`, `/v1/chat/completions`, `/v1/responses`, and `/v1/responses/compact` return **402** with `error.type` and `error.code` set to `insufficient_quota` when the local account balance or subscription quota cannot cover pre-consume. This includes zero balance and a positive balance below the required amount.

```json
{
  "error": {
    "message": "insufficient_quota: Account balance or subscription quota is insufficient for this request. 用户余额或订阅额度不足，无法完成此次请求。 (request id: ...)",
    "type": "insufficient_quota",
    "param": "",
    "code": "insufficient_quota"
  }
}
```

A streaming request receives the same JSON error **before** an SSE stream starts. Treat this as a terminal quota failure: check the account balance or subscription allowance before trying again. Do not refresh credentials, switch channels, or retry with backoff solely because of this response. The message includes a request ID; detailed quota amounts remain in server diagnostics.

This normalization is limited to local account-quota failures on these endpoints. Token validity/quota errors, upstream provider errors, and other API protocols keep their existing contracts. A genuine 401 or permission 403 still requires an authentication/access check; an ordinary 429 remains a rate-limit response.

## Channel passthrough precautions

<Warning>
  These channel-setting changes were deployed on October 4, 2026. Passthrough is controlled by the service operator, not enabled by an ordinary API caller; consider the risks of disclosing information to the upstream.
</Warning>

**Body passthrough** forwards the request body without the usual gateway rewriting. Do not rely on model redirection, parameter overrides, injected system prompts, or format conversion in that mode; the client must use a format and model name the upstream supports. Use `X-Omnimux-Group` for group selection when the upstream does not understand a `model@group` suffix.

**Header passthrough** can disclose client version, session information, User-Agent, IP-related headers, and custom header values to the upstream. The wildcard/regex forwarding rules exclude standard authentication, cookie, and transport headers; this is not a guarantee that every custom secret header is filtered. Do not put secrets or unnecessary personal information in custom headers. Forwarded headers can override gateway defaults and cause upstream errors; explicit channel header overrides take precedence.

A successful connection or a model listed locally is not proof of successful generation, availability in a particular group, or correct billing. Use the live catalog and the published model contract, and verify the actual output and final charge for your integration.

## Unexpected content

- Use live model ids  
- Chat needs valid `messages`; social-data needs business fields  
- Video poll: `GET /v1/video/generations/{task_id}` only — not `/v1/videos/*/content` for Omni Flash / MiniMax creates  

## Cannot connect

- Firewall/proxy TLS to `api.omnimux.ai`  
- Many OpenAI SDKs need base ending with `/v1`  
- Probe with `GET /v1/models`
