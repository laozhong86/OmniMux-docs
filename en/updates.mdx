<a id="2026-10-23-h3-unoffered-resolution-rejected"></a>

<Update label="October 23, 2026" tags={["Improvements", "Video"]} rss={{ title: "H3 video: unoffered resolution tiers are rejected explicitly" }}>

  ## Change

  `minimax-h3-video` supports three billing tiers: `480p`, `736p` and `768p`. The upstream-only `1088p` and `1440p` tiers were wrongly reachable through the public enum; they are removed now, so a request carrying one returns `400` (`plugin_usage_invalid`).

  ## Impact

  - The model bills per second and has no resolution dimension, so `1088p` / `1440p` cannot be priced on their own. Before this change such a request was accepted and precharged at the base rate (measured: 12500 raw_quota), the upstream run ended in `FAILED`, and the quota was refunded in full — the tier had neither a price nor a reliable run.
  - Unoffered tiers now fail closed: the request is rejected instead of being silently downgraded to `768p` or billed as `768p`.
  - The published `480p` / `736p` / `768p` contract and prices are unchanged.

<Update label="October 23, 2026" tags={["New models", "Video"]} rss={{ title: "MiniMax H3 video line restored with tier groups" }}>

  **MiniMax H3 video line** (`minimax-h3-video`) is available again, served by AutoDL ComfyUI workflows.

  ## Restored

  - **Model ID:** `minimax-h3-video`
  - **Contract:** `POST /v1/videos`, polled through `GET /v1/videos/{task_id}` (plugin line: the path differs from the other video series models, and `/v1/video/generations` returns 503)
  - **Tiers:** standard (default, 1.0×), `minimax-h3-video-fast` (0.9×), `minimax-h3-video-pro` (1.15×)
  - **Billing:** 0.025 USD/second (¥0.17/second at FX 6.8); `raw_quota = 0.025 × 500000 × seconds × GroupRatio`

  ## Capabilities and limits

  - One ID selects its endpoint from the request shape: text-to-video, image reference, image + audio, lip sync and first-last frame. When nothing matches it returns 400 instead of silently falling back.
  - The fast and higher-quality tiers serve image reference and image + audio only, capped at 768p.
  - Offered resolutions are 480p / 736p / 768p. 1080p and the higher upstream tiers have no published price and are not offered.
  - Duration is 1–15 seconds (default 5); some shapes cap at 10 or 12 seconds.

  ## New parameter

  - `mode` (`高速模式` / `高质模式`, default `高质模式`): accepted by the nine-image and nine-image-three-audio endpoints added on 2026-10-23.

<a id="2026-10-20-viral-recreate"></a>

<Update label="October 20, 2026" tags={["Improvements", "Video"]} rss={{ title: "Viral recreation: analyze a reference clip, then generate from the compiled prompt" }}>

  Viral recreation adds a reference-video analysis step to the account creation API. The reference clip is **decomposition material only**: it never enters a generation model, so the later generation request carries images and one compiled prompt and no video or audio reference.

  ## New endpoints

  - `POST /api/influencer/v1/recreations/analyze` (`influencer_creation:write`) accepts a 4-15 second public HTTPS clip (MP4/MOV, at most 64 MiB), 1-9 reference images and an optional creative intent of up to 1200 characters. It answers HTTP 202 with `{task_id, status: "waiting", progress: "0%"}`.
  - `GET /api/influencer/v1/recreations/{task_id}` (`influencer_creation:read`) reports `running`, `success` or `failed`. Success carries one compiled prompt, a `viral-recreate.analysis/1` structured breakdown, one reading per reference image, and `meta` with the derived `duration_sec`, `reference_duration_sec`, `aspect_ratio: "9:16"` and `pricing`.

  ## Generation

  `POST /api/influencer/v1/videos` accepts `mode: "recreate"`. It takes no reference video, requires `prompt` plus `image_urls`, requires `duration_sec` equal to the analyzed `meta.duration_sec` (whole seconds, 4-15), fixes framing to `9:16`, and accepts `resolution` `480p` or `720p`.

  ## Billing and limits

  - Analysis is not billed separately; its cost is included in the generation price.
  - `meta.pricing` reports the exact credits per selectable quality at the derived duration, so the generate control can show the amount the pre-charge takes instead of an estimate. Recreation is the only video mode with a precise upfront quote.
  - Each account has 20 analyses per day by default (server-configurable). Excess returns 429 `recreate_analysis_limit` with `Retry-After`.
  - An unparseable clip, a clip outside 4-15 seconds, or a failed prompt gate ends the analysis job as `failed` with a public `message`; the analysis itself bills nothing.

<Update label="October 16, 2026" tags={["Breaking", "Image"]} rss={{ title: "GPT Image standard specifications and routing safeguards" }}>

  The standard service is quoted per image and accepts JSON requests only, with `medium` quality and PNG output. Seven aspect ratios map to exact pixels: 1:1 (1024x1024), 2:3 (1024x1536), 3:2 (1536x1024), 3:4 (1024x1360), 4:3 (1360x1024), 9:16 (1088x1920), and 16:9 (1920x1088). The old 1365-pixel edge for 3:4 / 4:3 changes to 1360. Old explicit sizes are rejected rather than silently replaced.

  The complete prompt must satisfy all three limits: **8192 Unicode code points, 16384 UTF-8 bytes, and 5000 tokens counted by this service with `o200k_base`**. The service token count determines request eligibility; it does not represent final supplier billing usage or guarantee a per-request procurement cost ceiling. The vendor's 32000-character fact and existing contracts for the separate Flare / Sunburst models are not changed by this standard-service restriction.

  Multiple output images, multiple references, higher quality, other output formats, and unreviewed extensions are explicitly rejected. Identified standard-route public requests are rejected before creating a supplier task or reserving funds; queued workbench tasks may fail explicitly without a charge after validation. Standard and member prices are shown before submission. Switching an eligible route within the same account tier does not add a customer charge.

  A reviewed backup may be attempted only when no supplier task was created on the preferred route and native retry rules and the total attempt budget allow it. Two healthy routes are not guaranteed at all times. Accepted tasks and tasks with timeouts, disconnections, or missing acknowledgements are reconciled against the original request without automatic duplicate generation. Old failed tasks are not automatically resubmitted.

<a id="2026-10-12-motion-framing-contract"></a>

<Update label="October 12, 2026" tags={["Improvements", "Video"]} rss={{ title: "Reference video and output framing contracts separated" }}>

  Input media and output framing were previously coupled: the reference clip had to match one of 16:9, 9:16, or 3:4, and the same value was sent as the output ratio. That produced a misleading "unsupported aspect ratio" error for clips such as 5:4, and let the form offer 3:4 on 720p even though the bound 720p line only evidences 16:9 and 9:16.

  The contracts are now separate. The clip's own ratio is input metadata, not an eligibility gate: a non-standard clip can still drive motion transfer, which gains an independent Frame setting bounded to what the bound line can produce. Object swap must preserve the reference framing, so it submits only when the clip's own ratio is standard and producible on the chosen tier — 480p allows 16:9, 9:16, 3:4; 720p allows 16:9, 9:16 — and otherwise stops before generation with an accurate reason. The workbench never crops, stretches, or letterboxes the clip silently.

  The workbench now also exposes GET /pg/influencer/motion/options (session-only), so the form offers only the output framings the bound lines evidence, without revealing channel or vendor details. Server-side media inspection, duration bounds, audio extraction and native billing are unchanged.

<a id="2026-10-10-reference-media-checks"></a>

<Update label="October 10, 2026" tags={["Improvements", "Video"]} rss={{ title: "Reference-video preparation checks" }}>

  The checks are scoped to reference-video preparation in the character workbench, not all generic video API requests. The workbench checks the complete actual media for a duration of 4 to 30 seconds, without trimming an overlong video or audio tail or speeding it up. Submitted integer duration must match the rounded actual media duration; an explicit aspect ratio must match the displayed frame.

  The intake ceiling remains 100 MiB (104857600 bytes), not a verified limit shared by every supplier option. Complete supplier input contracts remain unverified. Valid small files do not require compression; automatic compression is not enabled.

  Generation uses a copy of the same validated video bytes without transcoding and keeps the complete embedded audio. A separate optional audio reference is attached only for a fully extractable reference of at most 15 seconds; longer references are not replaced with shortened audio. Use `tiktok_direct` for official TikTok accounts or `zernio` for Zernio accounts. GET/DELETE carry it in the query; POST carries it in JSON. Missing or unknown values return `400 invalid-provider`; a resource from another source returns `409 account-provider-mismatch` or `409 post-provider-mismatch`. There is no default source.

  ### CLI migration

  Use CLI **0.4.0**: `omnimux update` for binaries, or `npm install -g @omnimux/cli@0.4.0` for npm. Update all saved commands to include `--provider`, for example `omnimux social accounts --provider zernio`. For a read without upstream refresh, use `omnimux social post-status <post-id> --provider zernio --no-refresh`. Updating a binary does not update your scripts or prove all clients have upgraded.

  CLI 0.4.0 also includes the previously merged hosted commands and video skill updates. Credentials use a mode-0600 file on every platform; Keychain-only installations need credentials configured securely. The Agent RPC envelope remains `contract_version: 1`.
