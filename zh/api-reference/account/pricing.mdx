- 公开目录接口，无需鉴权。
- 每个在售模型行都带 `contract` 对象：包含模型级能力包络，以及 Contract v2 起提供的可执行操作列表。

## 身份

| 字段 | 值 |
| --- | --- |
| 系列 | 账户管理 |
| 能力 | 公开定价 |

## 接口

| 方法 | 路径 |
| --- | --- |
| `GET` | `/api/pricing` |

Base URL：`https://omnimux.ai`

## 响应

### 200

`data` 是模型数组。每行包含 `model_name`、`quota_type`、`model_ratio`、`model_price`、`enable_groups`、`default_group`、`group_order` 和 `contract`。

顶层 `pricing_version` 标识定价展示契约版本，当前值为 `"model-group-display-v1"`。

| 展示字段 | 含义 |
| --- | --- |
| `default_group` | 服务端下发的默认选中分组。非空时保证同时属于该模型的 `enable_groups` 与当前调用者的 `usable_group`；管理员显式配置的默认组对当前调用者不可用时为 `""`；缺显式配置时按「调用者分组 → `default` → `group_order` 首个可用组」回退。 |
| `group_order` | 模型级线路/分组展示顺序，去重且覆盖该模型全部 `enable_groups`；仅用于展示排序，区别于自动路由候选分组 `auto_groups`。 |

可选的顶层 `defaults` 按操作推荐模型（`chat`、`vision_chat`、`text_to_image`、`text_to_video`、`text_to_music`、`speech_to_text`）。每个值都指向同一响应中 `enable_groups` 非空的模型；没有可用推荐时省略对应键。

`contract` 是纯描述数据，不参与计费、额度或结算。

| 契约字段 | 含义 |
| --- | --- |
| `schemaVersion` | 契约形态。`"2.0"` 表示 `operations` 是对象数组。 |
| `contractVersion` | 每个模型独立的内容哈希；客户端可据此只缓存/刷新变化的模型。 |
| `operations[]` | 可执行操作。每项含 `id`、`executable`、`inputs[]`、`parameters[]`、`output.type`。 |
| `operations[].modeKind` | 可选的视频模式本地化键。Muse 图片参考使用 `image_reference`，Seedance 全能参考使用 `multimodal_reference`。提交请求时填写操作的 `id`。 |
| `operation_ids[]` | 同一批操作 ID 的字符串数组，兼容 v1 客户端。 |
| `unknowns[]` | 治理档案未建立的字段路径；缺失字段不是默认值。 |
| `reference_images` / `reference_videos` / `reference_audios` | 参考素材数量、格式与大小上限。 |
| `reasoning_efforts` | 可选：文本模型的推理档位到上游 wire value 的映射。 |
| `default_reasoning_effort` | 可选：默认推理档位；存在时必须是 `reasoning_efforts` 的键。 |

操作输入项包含 `slot`、`type`、`role`、`firstItemRole`、`required`、`min`、`max`、`allowedMimes`、`maxSizeMb` 及已声明的时长边界。参数项包含 `name`、`type`、`enum`、`minimum`、`maximum`、`step`、`default`、`fixed`、`limitSource`。

`executable: false` 表示厂商文档列出了该操作，但本网关不支持执行；客户端不得提交。

## 视频分组能力

`GET /api/pricing` 的模型行与 `GET /api/model_contract/:model` 的响应可在 `contract` 同级返回 `effective_video`，用于声明了 `contract.gateway_protocol: "video_generations"` 或已登记并核验分组规则的视频模型。它是当前账号可选分组的视图：`groups` 将每个分组映射到完整操作变体数组，`version` 随该视图能力内容变化。没有视频能力视图的模型不返回 `effective_video`；旧客户端继续使用模型级 `contract` 和既有调用方式。

| 字段或状态 | 含义 |
| --- | --- |
| `effective_video.version` | 当前账号分组能力视图的内容版本。模型级契约版本仍取自 `contract.contractVersion`。 |
| `effective_video.groups` | 将当前账号可选分组映射到完整操作变体；不在调用者 `usable_group` 内的分组不会返回。 |
| 省略 `effective_video` | 当前没有账号级分组视图；沿用模型级 `contract` 和既有调用方式。 |
| `groups` 为空对象或组内为空数组 | 空对象表示当前账号没有可发布的分组；组内空数组表示该组没有经核验的变体，不应回退到其他分组。 |

变体包含 `id`、可选的 `gateway_protocol`、`modeKind`、`inputs`、`parameters` 和 `output`。同一操作 `id` 可以有多个素材上限或参数约束不同的变体。请求的素材槽数量、必填参数等必须同时匹配一个变体；`required: true` 要求调用方显式传值。有序图片参考的 `firstItemRole: "first_frame"` 表示第一张参考图用作起始图。经核验的 profile 可以相对模型级契约收窄 `modeKind` 与实际接受的素材角色。

### 协议继承

先读取所选变体的 `gateway_protocol`；缺省时继承模型级 `contract.gateway_protocol`。当所有分组均与模型默认 `contract.gateway_protocol` 一致时，变体省略该字段；混合协议模型（或与模型默认协议不同的变体）会在变体上显式发布 `gateway_protocol`，并以所选分组的变体协议为准。

| 协议 | 创建 | 查询 |
| --- | --- | --- |
| `openai_video` | `POST /v1/videos` | `GET /v1/videos/{task_id}` |
| `video_generations` | `POST /v1/video/generations` | `GET /v1/video/generations/{task_id}` |

模型默认协议为 `openai_video` 且选择原生 `video_generations` 变体时，创建走 `POST /v1/video/generations`，并携带 `X-OmniMux-Video-Protocol: video_generations`；查询该任务走 `GET /v1/video/generations/{task_id}`。`openai_video` 默认仍使用 `POST /v1/videos` 和 `GET /v1/videos/{task_id}`。旧客户端不带请求头访问原生入口时，保留模型原有的默认解码行为。

### 选择与重试

目录反映查询时账号可用的分组。通过请求模型字段中的 `model@group` 显式选择分组；该分组约束本次提交及每次重试，请求必须匹配 `effective_video.groups[group]` 中的一个完整变体。已受理任务按原始任务记录和协议查询，即使后续目录或分组规则变化也不切换。`400 video_capability_mismatch` 表示当前没有已核验候选接受该组合；`503` 表示当前没有可用的已核验候选。

Seedance 2.5 请求带源视频或参考视频时，`operation` 填 `video_edit`、`video_extend` 或 `video_multi_ref`，网关据此确定上游任务类型。也可传对应的 `omni_reference_task_type` 值 `edit`、`extend` 或 `reference`。请求携带 `draft: true` 或非空 `draft_task_id` 时返回 HTTP `400`。

## 相关接口

`GET /api/model_contract/:model` 返回 `data.contract`，以及整份静态契约文档的版本 `data.version`。具备视频能力视图的模型通过 `data.effective_video` 返回与定价模型行结构相同的账号分组能力。模型没有治理档案时返回 `404`。
