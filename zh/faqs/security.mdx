## 如何保管 API Key？

- **不要**把 `sk-` 写入公开仓库、前端打包产物或截图  
- 使用环境变量 / 密钥管理服务  
- 泄露后立即在控制台轮换/作废  
- 开发、预发、生产尽量使用不同 Key，便于撤销  

## 两套凭证

| 凭证 | 用途 |
| --- | --- |
| `sk-` API Key | 网关推理、社交数据读等 |
| 用户 access token + `New-Api-User` | 设备码登录后的用户 API、社媒发布 |

不要用 `sk-` 去调发布接口，也不要用用户 token 冒充网关 Key（除非产品明确支持）。

## 最小权限习惯

- 只给自动化机器人所需模型的分组/权限  
- 日志中不要打印完整 Key  
- 分享「示例 curl」时使用占位符 `<token>`

## 升级后的第三方网页登录

以下为升级说明，相关保护在对应网关更新部署后生效；文档发布不代表正式服务已经部署。

使用第三方账号登录时，请在发起登录的同一浏览器及同一浏览器资料中完成登录，并允许该浏览器保留本站为本次登录设置的 Cookie（浏览器凭据）。登录状态参数和返回地址本身不足以完成登录；回到本站时，还必须携带发起该次登录时设置的对应浏览器凭据。

不要把未完成的登录回调链接复制到另一浏览器、另一浏览器资料或无痕窗口中继续。若凭据丢失、被清除或登录已过期，请回到登录页重新发起登录。升级前尚未完成且未绑定浏览器凭据的登录流程也需要重新开始。

多次分别发起的登录各自保存凭据；完成一次不会清除另一次的对应凭据。已登录账户的第三方账号绑定和安全验证仍要求使用发起操作时的账户会话。
